# 변형문제 검수 규칙

문항을 만들 때마다 코드가 자동으로 보는 것들. **고칠 수 있는 것은 고치고, 못 고치는 것만 버린다**
(만들다 버린 값도 우리가 내므로).

버려지면 다른 유형으로 바꿔 한 번 더 만들고, 그 문항에는 「다른 유형으로 바꿔 만든 것」 표시와
**왜 안 됐는지**가 남는다(`validation_result.substitutedFrom` / `substitutedReason`, 작업 기록에는 까닭별 셈).

---

## 1. 고쳐 쓰는 것 (버리지 않는다)

| 무엇이 잘못되면 | 어떻게 고치나 | 자리 |
|---|---|---|
| 밑줄 기호가 `ⓐ ⓑ ⓓ ⓒ` 처럼 뒤바뀜 | 나온 차례대로 다시 매기고 정답·해설·묻는 글의 기호도 함께 옮긴다. 글자는 하나도 안 바꾼다 | `renumber-marks.ts` |
| 요약문 빈칸이 `ⓑ____ … ⓐ____` 로 거꾸로 | 같음. 차례는 **빈칸에 붙은 기호로만** 센다(조건 줄의 「ⓐ는 세 단어」까지 세면 이미 맞는 것으로 보인다). 조건 줄의 기호도 함께 옮겨지므로 「ⓑ는 세 단어」와 ⓑ의 답이 맞는다 | `renumber-marks.ts` |
| 정답 기호가 `ⓓ … / ⓑ …` 처럼 섞임 | `ⓐⓑⓒ` 차례로 늘어놓는다 | `renumber-marks.ts`, `grammar-fix-normalize.ts` |
| 어법 수정 정답의 고친 말이 해설과 어긋남 | **해설을 더 믿는다.** 해설의 `기호 → 고친 말` 짝으로 정답을 다시 적는다 | `grammar-fix-normalize.ts` |
| 해설이 「맞음」이라 한 기호가 정답에 들어 있음 | 정답에서 뺀다. 그래서 둘 미만이 되면 버린다 | `grammar-fix-normalize.ts` |
| 제시어배열 빈칸이 문장 끝 마침표까지 삼킴 | 마침표를 돌려준다. 빈칸이 문장 하나를 통째로 차지할 때만(앞이 문장 끝이거나 글머리) | `blank-line-overlap.ts` |
| 빈칸 문장에 보기 낱말이 그대로 남음 | 빈칸을 그 문장 전체로 넓혀 본다. 넓혀도 남으면 버린다 | `blank-line-overlap.ts` |
| 순서추론 정답이 `(A)-(B)-(C)` 꼴 | 라벨을 돌려 준다(①만 찍어도 맞던 것을 막는다) | `order-relabel.ts` |
| 어법 수정 답칸 수 | **늘 큰 칸 하나.** 칸 수로 개수가 새지 않게 | `generate-question.ts` |
| 보기 차례가 치우침 | 객관식 보기를 섞고 정답 번호를 따라 옮긴다 | `generate-question.ts` |

## 2. 버리고 다시 만드는 것

### 모든 유형
- 발문·해설이 비었다
- **모델이 답 대신 틀(`grade`·`difficulty`·`forcedInstruction`·`schema`)을 그대로 되돌려 준다**
  → 지시문에 「OUTPUT KEYS를 채워라, 이 덩어리를 베끼지 마라」를 박아 막는다
- 지문·보기에 한글이 섞였다(발문·해설만 한국어)
- 정답 번호가 보기 범위를 벗어난다

### 어법·어휘
- **지문을 고쳐 썼다** — 원문 낱말이 90% 미만 남았다(`PASSAGE_KEEP_MIN`). 「어법·어휘는 원문 그대로」가 기준
- 해설이 정답과 다른 번호·기호를 가리킨다
- 「개수」 유형: 정답 숫자와 해설이 든 틀린 개수가 다르다
- 어법 수정: 실제 오류가 둘 미만이다(「모두 고르기」 발문과 어긋난다)

### 서술형
- 제시어배열: `<조건>`·`<보기>`·`<해석>`이 줄 단위로 서지 않았다
- 요약표: `<조건>`·`<표>`가 줄 단위로 서지 않았다
- 조건에 적은 단어 수와 정답의 낱말 수가 다르다(`ⓐ`·`ⓑ`를 **따로** 센다)
- 보기 낱말이 서른 개를 넘는다(낱말 마흔 개를 늘어놓고 배열하라는 것은 시험 문항이 아니다)
- 「본문에서 찾아 쓰기」인데 정답이 본문에 없다
- 지칭: 본문에 `<u>밑줄</u>`이 없다, 정답이 본문 연속 구가 아니다
- 문법조건영작: 정답 문장에 **지정한 어법이 안 보인다**

### 문장 수가 모자라는 유형
- 문장삽입·무관한문장은 지문 문장이 여섯 개 미만이면 **아예 만들지 않는다**(생략)

## 3. 학생에게 개수를 알려 주지 않는다

어법 수정 서술형은 몇 개가 틀렸는지 **어디에서도 새지 않게** 한다.
- 발문 — 「어법상 틀린 곳을 **모두** 찾아」 (「2개 찾아」·「3개 찾아」 아님)
- 답칸 — 큰 칸 하나(21mm). 세 칸을 두면 학생이 세 개인 줄 안다
- `<조건>` — 「틀린 곳의 기호와 수정한 형태를 모두 써야 정답으로 인정함」

## 4. 해설에 쓰지 않는 것

- **지문에 없는 문법 이름이나 포인트 번호**(`GP10 …`)를 지어 붙이지 않는다.
  제시어배열은 빈칸으로 쓸 문장을 차례(슬롯)로 고르므로, 문장을 고르는 데 쓴 POINT는
  그 문장의 문법과 더는 같지 않다. 해설은 그 문장 자체를 풀이한다
- 존댓말(「맞습니다」·「합니다」) — 「~다」로 끝나는 평서형으로 쓴다

## 6. 만든 뒤 한 번에 훑는 법

규칙 검수를 묶어 둔 것이 있다(모델 안 부른다).

```bash
# 가장 최근 작업
npx tsx --env-file=.env.local scripts/check-questions.mts
# 작업을 골라서 (id 앞 여덟 자)
JOB=24b4187a npx tsx --env-file=.env.local scripts/check-questions.mts
```

보는 것: 앱 검수 재적용 · 보기/정답 번호 · 기호 차례(본문·묻는 글) · 어법 정답지와 해설 ·
찾아 쓰기 정답이 본문에 있나 · 개수 유형 · 서술형 단어 수와 토막 · 제시어배열 보기 겹침 ·
해설의 문법 포인트 군더더기 · 바뀐 유형 · 정답 번호 쏠림.

> 규칙으로는 **「정답이 내용상 옳은가」를 못 본다.** 그건 사람이 읽어야 한다.
> 다만 「본문에서 찾아 쓰기」 정답이 본문에 실제로 있는지, 「개수」 정답이 해설과 맞는지는
> 확인하므로 가장 흔한 틀림 두 가지는 걸러진다.
